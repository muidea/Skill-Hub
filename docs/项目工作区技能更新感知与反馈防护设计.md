# 项目工作区技能更新感知与反馈防护设计

## 背景

`skill-hub` 的默认仓库是可复用 skill 的归档源。项目工作区通过 `use/apply` 获得 `.agents/skills/<skill-id>/` 副本，再通过 `feedback` 将项目内优化反馈回默认仓库。

当默认仓库中的某个 skill 已更新到更高版本，而项目工作区仍保留旧版本副本时，如果继续基于旧副本优化并执行 `feedback`，容易产生两个问题：

- 重复优化：用户或 agent 在旧版本上重复解决仓库新版本已经解决的问题。
- 反馈覆盖：旧版本工作区副本被自动 bump 后归档，可能覆盖或分叉默认仓库中的高版本内容。

目标是让项目工作区自动感知默认仓库 skill 更新，并在高风险反馈前阻断或引导刷新。

## 设计目标

- 默认仓库 skill 是 source of truth。
- 项目工作区 skill 副本必须记录来源版本与来源内容指纹。
- `status` 能区分“仓库已更新但本地未改”和“本地基于旧版本已改”。
- `apply` 在本地未改时可自动刷新到仓库高版本。
- `feedback` 默认禁止把低于仓库版本的工作区 skill 反馈回默认仓库。
- 需要人工判断的同版本分叉不得静默覆盖。

## 状态字段

在 `spec.SkillVars` 中增加来源指纹字段：

- `applied_hash`: 最近一次 `apply` 后项目工作区 skill 目录的内容 hash。
- `applied_commit`: 最近一次 `apply` 时来源仓库 HEAD。第一阶段可为空。

现有字段继续保留：

- `version`: 项目工作区当前 skill 版本。
- `status`: 最近一次状态检查结果。
- `source_repository`: 该 skill 的来源仓库。

第一阶段以目录 hash 作为可靠判定基础；仓库 commit 作为后续增强字段，不阻塞本轮闭环。

## 状态模型

比较对象：

- `repo_version`: 来源仓库 `skills/<id>/SKILL.md` 版本。
- `repo_hash`: 来源仓库 `skills/<id>/` 目录 hash。
- `local_version`: 项目工作区 `.agents/skills/<id>/SKILL.md` 版本。
- `local_hash`: 项目工作区 `.agents/skills/<id>/` 目录 hash。
- `applied_hash`: 项目状态中记录的最近一次 apply 来源 hash。

状态判定：

- `Synced`: `local_hash == repo_hash`。
- `Outdated`: `repo_version > local_version` 且 `local_hash == applied_hash`。
- `ModifiedAgainstOutdatedRepo`: `repo_version > local_version` 且 `local_hash != applied_hash`。
- `Modified`: `local_hash != repo_hash` 且 `local_version >= repo_version`。
- `SameVersionDiverged`: `local_version == repo_version` 且 `local_hash != repo_hash`，用于提示同版本内容分叉；第一阶段 `feedback` 仍允许按现有逻辑自动 bump patch 后归档。
- `Missing`: 项目状态中启用了 skill，但工作区文件缺失。

为了兼容现有 UI，第一阶段可把 `ModifiedAgainstOutdatedRepo` 和 `SameVersionDiverged` 作为新增状态常量；旧客户端至少仍能显示状态字符串。

## 命令行为

### status

`skill-hub status` 输出新增状态，并将 `applied_hash` 缺失的旧项目按保守规则处理：

- 如果 `local_hash == repo_hash`，补齐 `applied_hash` 并标记 `Synced`。
- 如果 `repo_version > local_version` 且缺少 `applied_hash`，标记 `ModifiedAgainstOutdatedRepo`，避免误判为可自动刷新。
- 如果 `local_version >= repo_version` 且内容不同，按 `Modified` 或 `SameVersionDiverged` 处理。

### apply

`skill-hub apply <id>` 从来源仓库复制 skill 到项目工作区，并更新：

- `version = repo_version`
- `status = Synced`
- `applied_hash = repo_hash`
- `applied_commit = repo_head`，后续增强

当 `status` 为 `Outdated` 且本地未改时，`apply` 是推荐修复动作。

### feedback

`skill-hub feedback <id>` 归档前必须执行 freshness preflight：

- 如果 `repo_version > local_version`，默认拒绝 feedback。
- 如果 `status == ModifiedAgainstOutdatedRepo`，拒绝 feedback，并提示先 `skill-hub apply <id>` 后重新合并修改。
- 如果 `status == SameVersionDiverged`，第一阶段沿用现有逻辑 bump patch 后归档；后续可增加严格模式要求用户先显式 bump 项目工作区版本。
- 如果 `local_version > repo_version`，允许 feedback。
- 如果 `local_version == repo_version` 且内容变化，沿用现有逻辑 bump patch 后归档。

本轮不新增 `feedback --merge`。后续可以增加显式合并模式，用于把旧版本本地改动迁移到仓库高版本之上。

## 收口顺序

1. 扩展 `SkillVars`，记录 `applied_hash`。
2. 为 skill 目录增加稳定 hash helper，供 `status/apply/feedback` 复用。
3. 更新 `apply`，写入 `applied_hash`。
4. 更新 `status`，识别 `ModifiedAgainstOutdatedRepo` 与 `SameVersionDiverged`。
5. 更新 `feedback`，在低版本或同版本分叉时拒绝归档。
6. 补充测试覆盖：
   - apply 后 state 记录 `applied_hash`。
   - 仓库高版本、本地未改时 status 为 `Outdated`。
   - 仓库高版本、本地已改时 status 为 `ModifiedAgainstOutdatedRepo`。
   - feedback 遇到 `RepoVersion > ProjectVersion` 时拒绝。
   - feedback 遇到同版本内容分叉时继续 bump patch 归档，保证既有优化流程不被破坏。

## 非目标

- 不自动把旧版本本地修改迁移到仓库高版本。
- 不在 `feedback` 默认流程中覆盖仓库高版本。
- 不改变 `push` 的远端发布授权语义。
- 不依赖 agent 自动判断两个自然语言 skill 内容哪边更优。
